# 聚焦清單、快速收工與接續卡：第一版驗證

- 日期：2026-10-20
- 分支：`feat/project-resume-workspace`

## 已交付

- **我的聚焦**：從本機專案列表或詳情加入／移除，上下移動調整順序；不限制三個、不依推薦分數排序，也不自動排除使用者選入的暫停／封存專案。
- **快速收工**：三欄預填現有 `memory.status`、`memory.blockers`、`nextAction`；下一步必填，其他兩欄可留空。一次保存內容與伺服器產生的收工時間，並保留其餘記憶、任務和生命週期。
- **接續卡**：清楚呈現目的、停點、下一步、阻礙、Git／任務事實。人工記下的下一步優先；僅在沒有人工內容時才使用並標示建議。
- 繁體中文／英文文案、鍵盤可聚焦的排序按鈕、空狀態、保存／錯誤狀態與窄螢幕排版。
- 收工草稿跨分頁、語言及背景更新保留；關閉前可取消離開；與記憶編輯／交接匯回互鎖，版本衝突不自動覆寫或重試。

## 儲存及分享邊界

- SQLite schema 升級至 **v5**，新增獨立 `workspace_focus` 及 nullable `projects.checkpoint_at`。
- 聚焦有自己的 revision，不改動專案內容 revision／活動時間；刪除專案與清除聚焦 ID 為同一交易。
- 舊專案不捏造收工時間；一般編輯或匯回若實際改變三個收工來源欄位，會取消目前內容的收工時間標記。
- 聚焦排序及收工時間不新增到遠端共享／交接 JSON。收工文字仍遵從既有分享政策，表單有明確提示。
- 本次沒有模型 API、聊天讀取、自動 Git 寫入、checkpoint 歷史、提醒或 IDE 工作階段恢復。
- v5 資料庫不保證能由較舊執行檔開啟；既有「拒絕未來 schema」保護仍保留。

## 自動測試

`npm run verify` 通過：TypeScript、**32 個測試檔／490 項測試**及 production build。

最終文案調整後，另跑 client API／接續 UI／雙語／insights 的 **4 檔 33 項測試**，並重新 build 與執行 `git diff --check`，均通過。

新增覆蓋包括：

- 聚焦順序、空清單、超過三項、磁碟資料庫重開、獨立 CAS 衝突與刪除回滾。
- 收工原子性、僅增加一次 revision、空白驗證、保留其他欄位、內容變更後時間失效。
- v1–v4 升級至 v5、migration 失敗回滾、拒絕 v6。
- 聚焦／收工 metadata 不洩漏至既有共享投影、請求保留 CSRF 與本機範圍。
- 人工下一步不被任務推薦蓋過、雙語 key／插值一致、可存取標籤及使用者原文跳脫。

## 瀏覽器互動驗證

使用 `AI Project Hub verification`，port **4318**，資料目錄 **`.local/verification`**。只操作獨立 fixture 專案，沒有使用日常資料庫或掃描使用者其他專案。

已確認：

- 加入三個專案（含暫停專案）、重新排序、加入第四個再移除；重新載入及停止／重啟驗證服務後，順序、語言與已保存的收工內容均保留。
- 表單三欄預填，只有空白的下一步不能保存。
- 收工草稿跨詳情分頁與中英文切換保留；記憶編輯會被互鎖，關閉會要求確認。
- 模擬另一個視窗更新同一專案後，舊 revision 保存回 **409**，完整草稿保留；確認捨棄後載入真正最新資料。
- 成功保存後 revision 只增加一次、時間與三欄一致；其他記憶及既有任務不變；接續卡顯示人工下一步，而非原任務標題。
- **1440×1000** 桌面及 **390×844** 窄螢幕：聚焦清單、收工表單沒有整頁／dialog 水平溢出，表單切為單欄。
- Console 中的 409 為刻意的衝突測試結果，非非預期錯誤；初始載入無失敗請求或 runtime error。

## 已知限制

- 本次驗證的是瀏覽器共用介面與資料層，**未執行 Electron 原生桌面 smoke test、安裝包建置或發布**。
- Vite production build 成功，但仍提示單一 JavaScript chunk 超過 500 kB（約 681 kB）；本次沒有擴大範圍進行拆包。
- 收工紀錄只保存目前一組內容與標記，不提供歷史版本還原；清除標記不代表過去從未收工。
